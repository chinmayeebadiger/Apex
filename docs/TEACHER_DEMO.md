## Optional: A Visible Website On ECS

Use this only after a successful rehearsal and if you have 10-15 minutes. It creates billable compute and a load balancer. The cost estimator does not currently estimate ECS, load balancers, or VPC networking accurately; a zero estimate for these means missing coverage, not free infrastructure.

Click **New**, then use:

```text
Create a small classroom demo of an ECS Fargate service running the public image public.ecr.aws/docker/library/nginx:stable on container port 80. Use one task with 256 CPU units and 512 MiB memory. Create a VPC with two public subnets, no private subnets, and zero NAT gateways. Give the Fargate task a public IP. Put an internet-facing Application Load Balancer in front of it on HTTP port 80, with a health check on /. Allow traffic to the task only from the load balancer. Do not use autoscaling, HTTPS certificates, Docker builds, CDK assets, custom resources, databases, or S3 buckets. Use a CloudWatch log group with one-day retention and removalPolicy DESTROY. Output LoadBalancerURL, ClusterName, and ServiceName. Generate a self-contained AWS CDK TypeScript entry file.
```

Review the generated resources before approval. The model may not follow every instruction exactly. This example intentionally exposes an HTTP demo endpoint; explain any security warnings rather than hiding them.

After successful deployment:

1. Apex -> Deployment outputs -> open or paste `LoadBalancerURL`. If it only contains a DNS name, prefix `http://`. Show the nginx welcome page. This proves deployed infrastructure can serve a container; it does not demonstrate a custom Node.js application.
2. CloudFormation -> the new `apex-gen-...` stack -> Resources. This is the inventory of everything that belongs to this example.
3. ECS -> Clusters -> the cluster from `ClusterName` -> Services -> the service -> Tasks. Show one running Fargate task and its image.
4. EC2 -> Load Balancers -> find the Physical ID/DNS name from the stack. Show listener port 80.
5. EC2 -> Target Groups -> the stack's target group -> Targets. Show a healthy target.
6. VPC -> Your VPCs -> find the VPC ID from Resources. Show its two public subnets. Confirm no NAT gateway belongs to this VPC.
7. CloudWatch -> Log groups -> the log group Physical ID from Resources. Show the container log stream.

## If Something Goes Wrong

- UI does not load: start the frontend using the command above.
- Pipeline is offline: check internet, refresh, and wait for the connected label. Do not repeatedly click Generate.
- Generation fails: explain the failure and use the rehearsal screenshots or existing backup. A synthesized template is required before deployment.
- Deployment fails: open the exact CloudFormation stack -> Events -> the failed resource -> Status reason. Show the real error; use Retry deploy only after fixing its cause.
- Empty Outputs: use CloudFormation Resources to find the actual resources. Outputs only exist if the generated template defines them.
- Resources missing: check Mumbai region and the exact stack name. The deleted ECS example is expected to be missing from active stacks.
- History trash icon: it removes frontend history; it does not delete AWS infrastructure. Use CloudFormation for teardown.

## Cleanup After The Presentation

For the new S3 example:

1. S3 -> the exact demo bucket -> **Empty**. Remove uploaded objects. If using a versioned backup, Empty must also remove versions and delete markers.
2. CloudFormation -> the exact new demo stack -> **Delete** -> confirm.
3. Watch Events until `DELETE_COMPLETE`. Check Resources for failures or `DELETE_SKIPPED` resources. A Retain policy can leave resources behind even when stack deletion completes.

For the optional ECS example, delete its exact generated CloudFormation stack and wait for `DELETE_COMPLETE`. ECS draining and networking cleanup can take several minutes. Verify the load balancer, tasks, and any NAT gateways are gone.

## Answers To Likely Questions

- **What did you build?** "The UI, generation/orchestration workflow, CDK synthesis sandbox, template analysis, approval and deployment flow, live events, and stored generation history. Claude supplies the initial generated code."
- **What is CDK?** "It lets me describe infrastructure in TypeScript. cdk synth converts that code into the CloudFormation template AWS deploys."
- **Is it a simulation?** "No. The generated stack creates actual resources, shown in AWS CloudFormation and the service consoles."
- **Is the cost exact?** "No. This prototype uses heuristic assumptions and fetches pricing metadata. Some resource types have no estimate yet."
- **Is it production ready?** "It is a working prototype. Production work includes authentication, stricter deployment permissions, broader validation and security coverage, and more accurate cost estimates."
- **Is deployment least privilege?** "The deployment role currently has AdministratorAccess so the supported ECS/VPC examples can run. Narrowing that role is a production improvement."
- **Where is the frontend hosted?** "On my laptop for this demo. The backend and generated infrastructure are in AWS Mumbai."

Close with:

> "I started with an English request, reviewed the generated infrastructure, approved it, and then verified the real resources in AWS. That is the complete workflow Apex implements."
